## Problem

Modern LLM agents are typically deployed as *frozen models*: their parameters remain fixed after pre-training, and the agent draws only on what fits in the context window. This creates a fundamental limitation — the agent is stateless and cannot learn from its own deployment experience. Fine-tuning at deployment is prohibitively expensive (requires large labelled datasets and GPU compute) and risks catastrophic forgetting. The paper asks: how can an LLM agent *continually improve from live experience without updating any model weights*, and do so in a way that is (a) theoretically grounded, (b) empirically effective, and (c) production-deployable?

## Key idea

Treat **reusable skill artefacts** (structured markdown files containing declarative specs, prompts, and executable code) as the unit of external memory. The agent then operates in a closed **Read–Write Reflective Learning** loop: a learned skill router retrieves the most behaviourally relevant skill for the current stateful prompt (read), the frozen LLM executes it (act), the environment returns feedback, and the system reflectively mutates the skill library — rewriting prompts, code, or specs — based on the outcome (write). All adaptation happens through evolution of externalised skills; the LLM parameters are never touched. This reframes continual learning as *memory evolution* rather than *weight evolution*.

## Method

**Formal setup.** The system is formalised as a **Stateful Reflective Decision Process (SRDP)** $\mathcal{D} = \langle S, A, P, R, \gamma, \mathcal{M}, p_{\text{LLM}} \rangle$, extending the standard MDP with an episodic skill memory $M_t$ and an LLM decision kernel. The agent's policy is:

$$\pi^\mu(a \mid s, M_t) = \sum_{c \in M_t} \mu(c \mid s, M_t) \, p_{\text{LLM}}(a \mid s, c)$$

where $\mu$ is the retrieval policy and $c$ is a retrieved skill. By augmenting state to $x_t := (s_t, M_t)$, the system recovers the Markov property as a **Reflected MDP**, and KL-regularised soft policy iteration over this MDP is shown (via Memento 2, Thm. 8) to converge to the optimal retrieval policy.

**Architecture.** A Memento-Skills agent coordinates:
- **Skill Library** — persistent folder structure of reusable skills (built-in atomic skills like web search/terminal + learned skills)
- **Skill Router** — behaviour-aligned contrastive retrieval model trained via single-step offline RL; routes by execution-success relevance rather than semantic similarity
- **Execution engine** — runs the retrieved skill through the frozen LLM
- **Reflection / Write** — attributes failure, rewrites skill folders (code, prompts, specs), updates utility scores; can generate a new skill from scratch if the router returns a "null skill"
- **Context manager** — maintains stateful prompt across read-write cycles

**Training the router.** Casts skill routing as a KL-regularised Boltzmann policy over skills. Synthetic router goals (positive + hard-negative queries per skill) are generated by prompting an LLM, then a contrastive embedding model is trained via offline RL to maximise execution-success reward.

## Results

Two benchmarks across 3 reflective-learning rounds (R0 → R3):

**General AI Assistants (GAIA):**
- Level 1: 58.6% → 96.6% (+38.0 pp)
- Level 2: 74.4% → 93.0% (+18.6 pp)
- Level 3: 45.5% → 72.7% (+27.2 pp)
- Overall relative improvement: **26.2%**
- Skill library grew from 5 atomic skills to 41 learned skills

**Humanity's Last Exam (HLE):**
- Per-domain gains ranging from +14.5 pp (Engineering) to +30.4 pp (Biology)
- Overall relative improvement: **116.2%**
- Skill library grew to 235 skills, clustered into 8 semantic groups (Search/Web, Quantum/Physics, Math/Chemistry, etc.)

**Ablation vs static library**: Memento-Skills improves GAIA and HLE test accuracy by **13.7 pp and 20.8 pp** over a static Read-Write baseline.

**Cross-task transfer** is strongest when the learned skill library aligns with benchmark domain structure.

> [!warning] Limitations
> - Results depend on the existence of structured task clusters — cross-task transfer gains are weakest when benchmark tasks are domain-disjoint from the learned skill library
> - The skill router requires synthetic query generation via LLM prompting, introducing a dependency on the generator LLM's coverage of realistic user queries
> - No direct comparison to RLHF/DPO-fine-tuned agents of equivalent compute budget — the "no parameter updates" framing is contrasted only against a static Read-Write baseline
> - Write operation is complex: failure attribution + file-level rewriting introduces many points where the reflection step itself can err, which the paper does not stress-test
> - Convergence guarantee is inherited from Memento 2 under KL-regularised assumptions; whether those assumptions hold when Write mutates skills (not just appends episodes) is not re-proved

> [!question] Open questions
> - How does skill library quality degrade or improve with longer-horizon deployment (1000s of rounds)?
> - Are skills learned on one benchmark transferable to genuinely novel domains, or does utility collapse outside the training distribution?
> - Can the Write operation be made more sample-efficient — does every failure require full skill-folder rewriting?
> - How does this compare to parameter-efficient fine-tuning (LoRA) at comparable total cost?
> - What safety properties hold when the agent can rewrite its own skill code?

> [!tip] My take
> This is a direct methodological cousin of the self-learning project's Phase 2 direction. Both approaches aim for continual LLM-agent improvement without fine-tuning, and both treat prompt/skill artefacts as the learnable parameter. The SRDP formalism provides a principled way to think about the self-learning pipeline's Classifier → Prompt Refiner → Evaluator → approve/reject loop as policy iteration over memory. The "behaviour-aligned contrastive router" is particularly relevant — it's a concrete mechanism for the Classifier's routing decision that could replace the current LLM-as-judge approach with a trainable retrieval model as enough Phase 1 data accumulates. Key caveat: Memento-Skills optimises for execution success on well-defined benchmarks (GAIA/HLE), which have ground-truth answers. The self-learning project operates on *underwriter preference*, where ground truth is a moving target — this may make the contrastive router harder to train without robust Golden Evaluator signal.
