## Problem

Automatic prompt engineering methods (e.g., OPRO, PE) rely on a high-quality benchmark to score and compare candidate prompts. Constructing such a benchmark is expensive and difficult in many real-world tasks where labeled examples are scarce or where the user's intent is ambiguous. Existing methods also fail to capture task nuance when trained only on easy/typical examples — the prompt gets calibrated to the mode of the distribution but not to its edges.

## Key idea

IPC (**Intent-based Prompt Calibration**) reformulates prompt optimization as an iterative *calibration* loop that jointly:

1. **Generates synthetic boundary cases** — adversarial, ambiguous, or edge-case inputs that a current prompt handles poorly, generated by a meta-LLM from the current prompt and failure patterns.
2. **Optimizes the prompt against the synthetic set** — the generated boundary cases expand and focus the effective training signal so that the optimizer sees exactly the cases most likely to expose prompt weaknesses, without needing a large pre-built benchmark.

The calibration loop alternates between: (a) running the current prompt, (b) diagnosing misclassifications via confusion matrix or error pattern analysis, (c) generating adversarial samples targeting the identified failure mode, (d) proposing a revised prompt from the augmented failure set, and (e) verifying the revision on a small labeled seed set.

For generative tasks, IPC first calibrates a *ranking prompt* (a comparator that selects the better of two outputs) and uses it as a proxy evaluator to score generative candidates — reducing annotation burden from per-candidate scoring to pairwise preference labels on a small seed.

## Method

### IPC loop (classification variant)

Given: task description, small labeled seed $\mathcal{D}$ (as few as 20 examples), meta-LLM $M_\text{opt}$, task LLM $M_\text{task}$:

1. Initialize prompt $p_0$ from task description.
2. For each iteration $t$:
   - Run $p_t$ on $\mathcal{D}$; collect misclassifications.
   - Prompt $M_\text{opt}$ with: current prompt + failure analysis → generate $k$ synthetic boundary cases $\mathcal{B}_t$.
   - Prompt $M_\text{opt}$ with: current prompt + $\mathcal{B}_t$ failures → propose revised prompt $p_{t+1}$.
   - Evaluate $p_{t+1}$ on $\mathcal{D}$; accept if improved.
3. Return best $p^*$.

### IPC for generation (ranking prompt extension)

1. First run the IPC loop to calibrate a *ranking prompt* $r^*$ that correctly orders outputs according to user intent (validated on a small pairwise-labeled seed).
2. Use $r^*$ as a proxy metric to evaluate generative prompt candidates without requiring human annotation per candidate.
3. Run a standard meta-prompt optimization loop (OPRO-style) with $r^*$ as the score function.

### Baselines

- **OPRO** — LLM-as-optimizer with standard prompt; no boundary synthesis
- **PE** — Prompt Evolution; iterative natural-language feedback without adversarial augmentation

## Results

Evaluated on real-world classification (content moderation) and generation (movie review writing) tasks with GPT-4/GPT-3.5:

- IPC achieves **higher accuracy** and **lower variance** than OPRO and PE on classification, particularly on ambiguous/imbalanced data where boundary cases dominate performance.
- IPC's generation variant outperforms baselines on pairwise preference alignment, producing reviews that better match user-specified intent dimensions.
- **Mean rank 4.8 / 5** across classification benchmarks vs. OPRO (rank 2.9) and PE (rank 3.1).
- Ablation confirms that **both components are necessary**: removing boundary synthesis or removing the intent-calibration loop each degrades performance materially.

> [!warning] Limitations
> - **Meta-LLM dependence**: boundary case quality is bounded by $M_\text{opt}$'s ability to generate adversarially representative samples. If the meta-LLM generates unrealistic edge cases, the calibrated prompt may overfit to artificial failure modes.
> - **Small evaluation scale**: results reported on 2 task families; generalization to diverse domains is untested.
> - **Synthetic boundary cases are not real failures**: the adversarial examples may diverge from the actual distribution of production inputs — a concern shared with all synthetic-data-based optimization approaches.
> - **No test-train split tracking of boundary cases**: it is unclear whether the synthesized boundary cases leak distributional information across iterations.
> - **Generation variant adds a double-loop cost**: calibrating the ranking prompt before optimizing the generative prompt doubles the optimization budget.

> [!question] Open questions
> - How does boundary case synthesis interact with **held-out test generalization**? Do prompts calibrated on synthetic boundaries overfit to the boundary distribution?
> - Can the **boundary case generator itself be improved** over iterations (adaptive adversarial generation)?
> - How does IPC compose with **trajectory-level reflection** (GEPA-style)? IPC generates synthetic failure cases before the loop; GEPA reflects on real trajectory failures during the loop — they operate on complementary signals.
> - Does the **ranking prompt calibration transfer** across tasks (similar to meta-learned system prompts)?

> [!tip] My take
> IPC is a clean solution to a real gap: most prompt optimizers assume you have a benchmark, but in many deployment scenarios the signal is sparse and the task is underspecified. The insight that you can *generate* the hard cases rather than *collect* them is simple and effective.
>
> The connection to the Optimisation Phase 2.1 note is direct: that note synthesizes UW feedback $z$ to validate a refinement loop — IPC shows that synthetic boundary cases can be as effective as real data for prompt calibration, with the caveat that they can introduce distribution mismatch. The ablation-recovery experiment in Phase 2.1 is essentially IPC's setting but with a known target $y^*$ instead of a ranking function, which is strictly easier. IPC's ablation component validates that synthetic signals are a reasonable proxy, but warns that the meta-LLM's adversarial generation quality is the ceiling.
